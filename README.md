# Netwatch для Orange Pi и Linux

Netwatch — круглосуточный монитор качества интернета для Orange Pi и других Linux-устройств с systemd. Каждые пять секунд он проверяет шлюз и два внешних узла, а результаты сохраняет в SQLite.

- **Каждый день в 04:15 по Брюсселю** — замер скорости скачивания и отправки, затем текстовый отчёт за последние 24 часа. Его можно получать в личном чате Telegram.
- **За завершённые периоды** — месячная сводка по дням, квартальная по месяцам и годовая по кварталам.
- **Хранение** — файлы отчётов находятся в `/var/lib/netwatch/reports` и удаляются после 365 дней. История измерений остаётся в SQLite.

## Установка одной командой

На компьютере с **Git, sudo, работающим systemd и IPv4-маршрутом** выполните:

```sh
git clone https://github.com/ellaleks/Netwatch-orange-pi.git && sudo bash Netwatch-orange-pi/install.sh
```

Установщик рассчитан на Debian, Ubuntu, Armbian, Fedora и Arch Linux. Для других дистрибутивов с systemd он может использовать уже установленные Python 3.9+ с SQLite, iproute2, iputils-ping, curl, сертификаты CA, tzdata и util-linux. На Debian 13 и Orange Pi Lite проверен сам Netwatch. Установщик не привязан к архитектуре процессора.

Он определяет интерфейс и шлюз по IPv4-маршруту, устанавливает недостающие зависимости через системный менеджер пакетов, запускает ping-службу и включает ежедневный замер скорости. Службы работают от непривилегированного пользователя. При обновлении существующей установки сохраняются база и её владелец, а службы получают новые файлы проекта. Служба ping при этом перезапускается.

Если сеть использует VPN или несколько подключений, можно явно выбрать интерфейс и шлюз. Если замеры скорости не нужны, добавьте `--no-speed`:

```sh
sudo bash Netwatch-orange-pi/install.sh --interface eth0 --gateway 192.168.1.1 --no-speed
```

Параметры сети хранятся в `/etc/netwatch/config.ini` и используются при повторной установке. Внешние адреса — Cloudflare `1.1.1.1` и Google `8.8.8.8`. Чтобы обновить уже клонированный проект, выполните `git -C Netwatch-orange-pi pull --ff-only && sudo bash Netwatch-orange-pi/install.sh`. Если нужен только ping, передавайте `--no-speed` и при обновлении.

## Где искать файлы отчёта

Готовые текстовые файлы находятся **на устройстве, где работает Netwatch**, в каталоге `/var/lib/netwatch/reports`. Пример имени файла — `netwatch-2026-11-05_04-15-07+0100.txt`. В имени указаны дата, время создания по Брюсселю и смещение от UTC.

**С Windows через WinSCP:**

1. Подключитесь по SFTP с тем же адресом и пользователем, что в PuTTY.
2. В правой панели откройте `/var/lib/netwatch/reports` и скачайте нужный файл. Нажмите **F5**, чтобы обновить список. Скачанный файл можно открыть в Блокноте.
3. Если WinSCP сообщает, что доступ запрещён, скопируйте нужный отчёт в свой домашний каталог через SSH. Сначала посмотрите список файлов и замените имя в примере на имя нужного отчёта:

   ```sh
   sudo ls -lt /var/lib/netwatch/reports
   sudo install -m 0600 -o "$(id -un)" -g "$(id -gn)" \
       /var/lib/netwatch/reports/netwatch-2026-11-05_04-15-07+0100.txt "$HOME/"
   ```

   Затем скачайте копию из домашнего каталога через WinSCP.

Каталог создаётся вместе с первым сохранённым отчётом. Чтобы получить файл сразу, запустите `sudo systemctl start netwatch-speed.service`. Если файла всё ещё нет, проверьте `sudo journalctl -u netwatch-speed.service -n 20 --no-pager`.

## Месячные, квартальные и годовые сводки

После ежедневного замера Netwatch проверяет, есть ли сводки за последние завершённые календарные периоды по времени Брюсселя. Если за период есть измерения, сводка создаётся один раз:

| Файл | Группировка |
| --- | --- |
| `netwatch-monthly-YYYY-MM_created-…txt` | За месяц, по дням |
| `netwatch-quarterly-YYYY-QN_created-…txt` | За квартал, по месяцам |
| `netwatch-yearly-YYYY_created-…txt` | За год, по кварталам |

Сводки содержат потери и среднюю задержку по каждому адресу, количество успешных проверок и ошибок, средние скорости скачивания и отправки. Интервалы без измерений указаны отдельно. Сводки сохраняются в `/var/lib/netwatch/reports`. Ежедневный отчёт по-прежнему отправляется в Telegram, если доставка настроена.

Тогда же Netwatch удаляет свои текстовые отчёты, которым больше **365 дней по дате создания в имени файла**. База SQLite и файлы с другими именами сохраняются. Если замер по расписанию отключён, можно запустить создание сводок и очистку вручную без теста скорости:

```sh
sudo -u "$(systemctl show -p User --value netwatch.service)" \
    /usr/bin/python3 /usr/local/lib/netwatch/netwatch-report.py --maintenance
```

## Отправка отчёта в Telegram

По желанию Netwatch отправляет готовый `.txt` в личный чат с ботом сразу после сохранения ежедневного отчёта. Если Telegram недоступен, отчёт остаётся в `/var/lib/netwatch/reports`, а причина записывается в журнал службы.

1. В Telegram откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot` и создайте отдельного бота для Netwatch.
2. После установки последней версии выполните на устройстве:

   ```sh
   sudo python3 /usr/local/lib/netwatch/netwatch_telegram.py
   ```

   Вставьте токен в скрытый запрос в терминале. Откройте ссылку, которую покажет программа, и нажмите **Start** в Telegram. Если кнопки нет, отправьте боту в личном чате точную команду `/start КОД`, которую покажет программа. Затем нажмите Enter в терминале. Если сообщение ещё не найдено, можно отправить ту же команду и нажать Enter снова. Программа привяжет личный чат по одноразовому коду. Токен хранится в закрытом файле `/etc/credstore/netwatch-telegram.json`.
3. Запустите пробный замер и проверьте доставку:

   ```sh
   sudo systemctl start netwatch-speed.service
   sudo journalctl -u netwatch-speed.service -n 20 --no-pager
   ```

   Успешная отправка отмечается строкой `Telegram delivery succeeded`. Дальше отчёты отправляются по обычному расписанию Netwatch. Чтобы отключить только отправку, переместите файл учётных данных за пределы `/etc/credstore` в закрытый каталог или удалите его.

## Отчёт и проверка

```sh
systemctl is-active netwatch.service
systemctl list-timers --all netwatch-speed.timer
sudo -u "$(systemctl show -p User --value netwatch.service)" \
    /usr/bin/python3 /usr/local/lib/netwatch/netwatch-report.py --hours 24
```

Отчёт разделяет отсутствие ответа, ошибки проверки и паузы сбора. `external_down` означает, что шлюз ответил, а оба внешних узла промолчали. `all_down` означает отсутствие ответа от всех трёх узлов. Границы событий приблизительны из-за интервала опроса. Раздел `Speed tests` показывает скорость скачивания и отправки за выбранный период, а также ошибки замеров.

Замер скорости запускается в **04:15 по Брюсселю** и передаёт около 12 МБ в день. После завершения службы отчёт за последние 24 часа сохраняется в `/var/lib/netwatch/reports`, даже если измерение скорости завершилось с ошибкой и база доступна. Старые отчёты остаются в каталоге. Файлы доступны пользователю службы и root.

Если плата выключена, запуск пропускается. Флаг `--no-speed` отключает замер и создание отчёта по расписанию. Чтобы сохранить датированный отчёт вручную без замера, добавьте `--save` к команде выше. Для проверки всей цепочки выполните `sudo systemctl start netwatch-speed.service`, затем `sudo journalctl -u netwatch-speed.service -n 10 --no-pager`.

Измеренная скорость относится к HTTPS-передаче с устройства через выбранный интерфейс. Во время теста задержка ping может вырасти.

База `/var/lib/netwatch/netwatch.sqlite3` хранит результаты ping в таблице `probes`, а интервалы, объёмы и скорость передач — в `speed_tests`. История накапливается без автоматического удаления. Для проверки запуска службы используйте `sudo journalctl -u netwatch.service -n 20 --no-pager`. Если установщик сообщает об ошибке прав ping, проверьте `sysctl net.ipv4.ping_group_range`. Для штатного выключения используйте `sudo poweroff`.
